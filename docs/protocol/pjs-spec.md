# PJS 投屏协议规范（v1）

本文档描述 **星联投屏** 电脑端（sender）与电视端（receiver）之间的全部线路格式。
代码实现：`sender-pc/src/pjs.h`（发送）、`receiver-tv/src/tv/projector/receiver/RxEngine.java`（接收）。
两者如有不一致，以本文档为准并修代码。

---

## 1. 端口

| 端口 | 方向 | 用途 |
|---|---|---|
| **45690** | PC → TV | 视频 / 音频 / META / CTRL，全部走这一路 UDP（单个 socket） |
| **45691** | TV → 广播 | 设备发现信标（`255.255.255.255` 或各网卡广播地址） |
| **45692** | TV → PC | 状态回传（`PJS/F1`）、pong（`q<ms>`）、忙提示（`PJS/B1`） |

PC 发送端使用一个临时端口（约 49xxx~65xxx），电视端把它显示为「电脑 IP:端口」。

---

## 2. 包头（16 字节，全部大端）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | magic | 固定 `0x50 0x4A`（ASCII `PJ`） |
| 2 | 1 | type | `0`=VIDEO，`1`=AUDIO，`2`=META，`3`=CTRL |
| 3 | 1 | codec | 视频 `0`=H.264；音频 `1`=AAC |
| 4 | 4 | seq | 每路独立的递增序号（u32，回绕按 32 位处理） |
| 8 | 4 | ts_lo | 时间戳低 32 位（微秒）。高 16 位由 META 携带，见 §4 |
| 12 | 1 | flags | 位标志，见下 |
| 13 | 1 | kind | 语义随 type 变化，见下 |
| 14 | 2 | payload_len | 负载长度（u16），**单包 ≤ 1200 字节** |

### flags

| 值 | 名称 | 含义 |
|---|---|---|
| `0x01` | FIRST | 该时间戳分组的第一个包 |
| `0x02` | LAST | 该时间戳分组的最后一个包 |
| `0x04` | IDR | 该访问单元是关键帧 |
| `0x08` | KEY | 关键包（发送端会把 KEY 包重发一次作为冗余） |
| `0x10` | RETR | 冗余副本（接收端据此丢弃重复） |

### kind（按 type 解释）

| type | kind | 含义 |
|---|---|---|
| VIDEO(0) | `0` | SLICE（H.264 分片） |
| AUDIO(1) | `1` | AAC（ADTS 帧） |
| META(2) | `2` | KIND_META（配置） |
| CTRL(3) | `0` | 文本指令 |

> **历史坑**：发送端曾把音频 kind 写成 `0`，而接收端只接受 `kind==1`，导致
> 音频被静默丢弃（界面显示 130kbps，电视 `aud` 恒为 0）。接收端现在两者都接受，
> 但新代码必须发 `1`。

## 3. VIDEO（type=0, kind=0）

- 只发 **slice NAL（1 / 5）**，SPS/PPS 由 META 承载（见 §4）。
- 一个访问单元（AU）的多个分片共享同一 `ts_lo`：第一个分片置 `FIRST`，最后一个置 `LAST`。
- 关键帧（IDR）置 `IDR` 标志；发送端还会整帧再发一遍并置 `KEY`（接收端用 `RETR` 去重）。
- 接收端按 `ts_lo` 边界把分片组装成完整 AU 后送入解码器；序号不连续视为丢包。

---

## 4. META（type=2, kind=2）

负载结构：

```
[ts_hi u16 大端][SPS + PPS（Annex-B，含起始码）]
```

- 恢复时间戳：`ts = ((uint64_t)ts_hi << 32) | ts_lo`（单位微秒）。
- 每次会话开始、以及编码器重建（分辨率/码率变化）后，**在关键帧之前**发送，必要时再补发。
- 负载超过 1200 字节时分包，`FIRST` / `LAST` 标记首尾。
- 接收端缓存 SPS/PPS，收到完整一对后再配置解码器；配置变化时重建解码器。

---

## 5. AUDIO（type=1, kind=1）

- **一个包 = 一个 ADTS AAC 帧**，不跨包、不拆包。
- 音频采样 48000Hz / 2ch / 128kbps（可调）。
- 时间戳与视频同源（同一 `ts_lo/ts_hi` 基准）。
- 接收端会把音频投递到独立 HandlerThread 的 AudioTrack 播放；音频超前视频过多时丢弃音频帧。

---

## 6. CTRL（type=3, kind=0，负载为 ASCII 文本）

| 负载 | 次数 | 含义 |
|---|---|---|
| `hi` | 3 | 会话开始：接收端复位重组器、重建解码器、等待关键帧 |
| `bye` | 3 | 主动断开：接收端立即释放解码器并回到等待页 |
| `ka` | 1/秒 | 心跳（静止画面且无音频时维持链路） |
| `p<毫秒>` | 1/秒 | 测延迟：接收端原样回 `q<毫秒>` 到 PC 的 45692 |
| `hn<名字>\t<端口>` | 3 | 上报计算机名与本机 UDP 端口（电视端展示来源设备） |
| `lk` | 2 | 电脑已锁屏：电视显示遮罩 |
| `ul` | 2 | 电脑已解锁：恢复画面 |
| `sw` | 2 | 发送端切换了显示器 |
| `probe` | 1/次 | 主动探测：接收端立即广播一次发现信标 |

> **RTT 时钟要求**：`p<ms>` 的时间戳必须与计算 RTT 时使用的时钟一致
> （目前两端都用 QPC / `steady_clock`）。历史上发送端用 `GetTickCount64()` 打戳、
> 用 `steady_clock` 相减，导致 RTT 恒定偏大 160ms。

## 7. 设备发现（45691）

电视端每秒广播一次（也可由 `probe` 触发立即广播），UTF-8 文本：

```
PJS/1
name=<设备名>
mod=<型号>
ip=<电视自报 IP>
port=45690
```

- **PC 以数据包的源地址为准**，忽略 `ip=`（电视换网线/DHCP 续租后 `ip=` 可能是旧值）。
- 同名设备只保留最新一条；超过 **3 秒**没有新信标即从列表移除。

---

## 8. 状态回传（45692）

电视端每秒回传一次，UTF-8 文本：

```
PJS/F1
fps=<电视渲染帧率>
lost=<自上次回传以来丢包数>
drop=<解码器丢弃的 AU 累计数>
idr=<收到的关键帧数>
aud=<音频帧累计>
adrop=<丢弃的音频帧累计>
res=<宽x高，未配置时为 ->
needidr=<1 表示正在等关键帧>
```

另有忙提示：`PJS/B1 busy=1`（已有其他电脑在投屏）。

PC 端的判定：

| 条件 | 结论 |
|---|---|
| 连续 **5 秒**没有收到 `PJS/F1` | 电视端已断开（退出码 7） |
| 收到 `busy=1` | 电视被占用（退出码 5） |
| 收不到 pong 超过 2 秒 | 界面「网络延迟」显示 `—` |

## 9. 发送端退出码

| 码 | 含义 |
|---|---|
| 0 | 正常结束 |
| 3 | 未授权 / 试用用尽 |
| 4 | 编码器创建失败 |
| 5 | 电视被另一台电脑占用 |
| 6 | 采集初始化失败（DDA 失败等） |
| 7 | 电视端断开（5 秒无回传） |
| 8 | WGC 创建成功但不出帧（界面据此用 `PJS_NOWGC=1` 重启一次，改走 DDA） |
| 9 | WinRT 异常 |

## 10. 会话时序（正常一次投屏）

```
PC                                          TV
 |-- hi ×3 -------------------------------->  |  复位重组器 + 重建解码器 + 等 IDR
 |-- META(ts_hi + SPS/PPS) ---------------->  |  配置解码器
 |-- VIDEO(FIRST|LAST|IDR|KEY) ×2 --------->  |  解码首帧
 |-- VIDEO(...) 持续 60fps ----------------->  |
 |-- ka 每秒 ----------------------------->  |
 |-- p<ms> 每秒 --------------------------->  |-- q<ms> --> 45692
 |<-------------- PJS/F1 每秒 ----------------|
 |-- bye ×3 ------------------------------->  |  释放解码器、回等待页
```

## 11. 已知的历史教训（改动时注意）

1. **音频 kind**：必须 `1`，否则接收端静默丢弃。
2. **RTT 时钟**：ping 打戳与计算必须同源。
3. **`hi` 的防抖**：只在「同一台电脑且会话仍活跃」时忽略重复 `hi`；换电脑必须重置。
4. **桌面静止**：没有新帧时发送端仍要每秒输出统计并补关键帧，否则接收端黑屏、界面卡「启动中」。
5. **限流器**：被拦下的帧不能推进令牌桶的「上次放行时间」，否则稳定丢一半帧（60→30fps）。
